# 角色动画表现层说明

## 范围

角色动画包括待机、地面行走、疾跑、推箱、拉箱、上升、下落、贴墙以及水底/水面待机和移动。推拉期间面向逻辑层指定的箱子，拉动时保持朝向并后退。

Animator Controller 不需要建立 Transition 或参数连线。`PresentationLayer` 通过 `Animator.Play` 直接选择已经关联好切片的 Base Layer 状态：

| 表现语义 | Controller 状态 | 切片类型 |
|---|---|---|
| 待机 | `On` | 循环 |
| 地面移动 | `move` | 循环 |
| 地面疾跑 | `Sprint` | 循环，8 帧 |
| 推箱 | `Push` | 循环，6 帧 |
| 拉箱 | `Pull` | 循环，6 帧 |
| 起跳/重新起跳 | `Jump_Up` | 触发动作，单次 |
| 持续上升 | `OnAir` | 循环 |
| 持续下落 | `OnAir_Down` | 循环 |
| 落地收势 | `Jump_Down` | 触发动作，单次 |
| 贴墙下滑 | `Wall` | 循环 |
| 水底悬浮待机 | `SwimIdle` | 循环，4 帧 |
| 水底移动（上下左右共用） | `Swim` | 循环，6 帧 |
| 水面待机 | `SurfaceSwimIdle` | 循环，4 帧 |
| 水面移动 | `SurfaceSwim` | 循环，6 帧 |
| 飞行 | `Flight` | 既有占位 |
| 死亡／精神体退场 | `Death` | 单次，实体 8 帧／精神体 12 帧；共用播放及实际完成等待已接入，普通动作不能覆盖 |
| 实体通关前段 | `LevelClear_0` | 单次，前 4 帧，0.64 秒 |
| 实体通关加载 | `LevelClearLoop_0` | 循环，后 4 帧，0.64 秒一轮 |

其中 `On` 与 `OnAir` 分别承载 `idle` 与 `OnAir_Up` 切片。五组新序列作为新资源导入，原有 `Swim`、`SurfaceSwim` 占位状态挂上移动片段，再新增疾跑及两种泳待机状态；新增状态没有连线，已有行走起步到行走循环的连线保留。

推、拉序列各为 1536×1024、3×2 布局，切片均为 512×512。`Push`、`Pull` 同在 Base Layer，没有新增连线，由表现层直接调用。

## 数据流

```text
PlayerStateMachine
  └─ ReadOnly_ActionData
       ├─ NowState / isSwimming / isSurfaceSwimming ► 贴墙、水底与水面行为
       ├─ onMove / verticalInput ─► 地面行走与泳待机/移动、左右朝向
       ├─ PushPullAction / PushPullBox ► 已成立的推拉行为与面向箱子
       └─ speedScale ─────────────► 状态机已结算的疾跑加速

CharacterPhysics / BasicEntity
  ├─ ReadOnly_GeometryPhysicsData
  │    └─ isGrounded ─────────────► 地面/空中边界
  └─ ReadOnly_PlayerPhysicsData
       ├─ verticalSpeed ──────────► 主动跳跃冲量检测
       └─ verticalSpeed+phyVSpeed ► 实际上升/下落阶段

PresentationLayer
  └─ Animator.Play / SpriteRenderer.flipX
       （只消费，不回写逻辑或物理）
```

表现层在 `Player.Update` 之后执行，以读取同一渲染帧内已经更新的逻辑输出；物理数据则始终读取最近一次完成的 FixedUpdate 快照。

## 触发动作与持续动作

- 触发动作只在状态边沿开始：物理层确认一次正向主动跳跃冲量时播放 `Jump_Up`，空中/贴墙转为着地时播放 `Jump_Down`。
- 持续动作表达当前行为：地面待机/行走/疾跑、持续上升/下落、贴墙以及水底/水面待机和移动。同一动画保持时不重新调用 `Animator.Play`，让循环正常推进。
- `Jump_Up` 是独立触发动作；完成后若仍在上升则交给 `OnAir`，开始下落或贴墙会提前中断它并立即切换持续状态。
- `Jump_Down` 只在着地后播放，完成后交给 `On`；再次离地、贴墙、跳跃或出现移动意图都会中断落地动作。
- 着地时物理层会把负的主动竖直速度重置为零；代码额外要求跳跃冲量的结果必须为正，避免把该归零误判成跳跃。

## 切换规则

1. 普通地面行为按水平移动意图选择 `On` 或 `move`；有移动意图且逻辑层 `speedScale > 1` 时选择 `Sprint`。体力和疾跑许可由 FSM 结算，表现层不读取原始疾跑键或重新推导许可。
   有水平移动意图、有效选中箱及已成立的 `PushPullAction` 时，优先选择 `Push`／`Pull`。只选中但尚在自动走近时、未选中的接触推动、解除选中后，仍按普通移动处理。零输入回待机；空中和水中行为优先于推拉。受阻时已有推拉意图仍播放用力循环。
2. FSM 确认贴墙时，播放 `Wall`。
3. 主动跳跃冲量成立时播放一次 `Jump_Up`；起跳动作结束且仍上升时进入 `OnAir`，开始下降时可提前打断。
4. 总竖直速度转为向下时直接进入持续状态 `OnAir_Down`，不再错误播放落地动作。
5. 从空中或贴墙状态进入地面时播放一次 `Jump_Down`；移动或再次跳跃可提前打断，随后进入相应持续状态。
6. 空中跳或墙跳会使主动竖直速度出现正向离散增量，据此从头重播 `Jump_Up`。
7. 顶点附近使用小速度死区并保持上一升降阶段，避免在零速附近反复切换。
8. 墙跳输入与物理结算分属 Update/FixedUpdate；离墙后会等待主动竖直速度产生下一次物理变化，再决定上升或下落，避免闪过错误动画。
9. 飞行、水面游泳、水底游泳优先于几何着地。泳姿由逻辑层状态区分；`onMove` 或 `verticalInput` 超过死区即播放移动，两者为零则播放待机。水流或水面追随造成的被动速度不触发主动划水。
10. 水面向上输入由逻辑层过滤为零；下潜输出负竖直意图，使用同一移动片段。纯上下移动保留已有左右朝向。跃出水面后的跳跃继续使用原有空中与跳跃动作。

## 新资源规格

疾跑与四种泳姿共 28 个 512×512 切片，以原待机的头部尺度为基准，PPU 为 118，显示尺寸为原 PPU=100 时的 84.75%。原图像素保持不变；泳姿保持固定 pivot。疾跑第 2、3、6、7 帧的支撑脚与待机脚底（局部 Y=-1.465）对齐，其余阶段插值竖直定位并保留第 5 帧腾空，水平定位与尺寸不变。疾跑每帧 0.08 秒，两种待机每帧 0.24 秒，两种移动每帧 0.16 秒，全部循环。

推拉共 12 个切片，原像素已按待机头部尺度调整，使用 PPU=100；pivot 为 (192.5,244.5) 像素，以待机原图中心为基准，支撑脚底与待机对齐。每帧 0.16 秒，每组循环 0.96 秒；不包含箱子图像，也不修改角色预设体和碰撞框。

原生 Unity 资源导入与核对工具为 `CatgirlSprintSwimAssets`（沿用入口并包含推拉）；表现层验收入口为 `CatgirlPresentationAnimationChecks.RunForBatch`。10/09 资源阶段的导入和验收记录写入 `output/animation-integration-20261009`，该阶段未修改物理与逻辑层生产代码。

2026-10-11 已导入确认的死亡／退场图片：实体和精神体各自的 `Art/sequence frame`、`Art/sequence frame2` 都使用 `catgirl-death.png`，切片名统一为 `catgirl-death_00` 起的两位序号。`Animation/Death.anim` 与 `Animation2/Death.anim` 的内部名称同为 `Death`，各自控制器统一通过 `Base Layer.Death` 寻址，关联对应素材，不添加 Transition、Any State 或参数。实体 8 格、单格 640×512、每帧 0.14 秒、总长 1.12 秒；精神体 12 格、单格 512×512、每帧 0.16 秒、总长 1.92 秒，最后一格完全透明。两者均非循环并保持末帧，PPU=100、固定像素 pivot=(192.5,244.5)，与原待机对齐。导入上限 4096，避免实体 2560 像素宽的图片被缩小。实际逐帧采样、结束保持、切片引用与既有状态保护通过，资源阶段记录见 `output/death-animation-integration-20261011`。

## 死亡与探索退场播放

`ValidateDeathPlayback` 校验制作配置；`TryBeginDeathPlayback` 返回本次播放身份；`GetDeathPlaybackStatus` 读取实际 `Base Layer.Death` 状态、对应非循环片段及 normalizedTime，报告无效／播放中／完成，不以固定秒数代替。播放独占期间停止普通动作与交互提示，使用真实时间且离屏仍推进，结束保持末帧；`CancelDeathPlayback` 作废旧身份并恢复 Animator 设置和普通动作选择。缺状态、片段不匹配、循环、无效速度或中途打断明确报错。

`PlayerLifecycleRules` 区分模拟遇险和实体死亡。模拟遇险直接沿原转换回漫游并扣一次原费用，保留现场，不建立动画等待，也不依赖死亡动画组件；世界按漫游规则暂停。实体死亡关闭输入、角色行为和资源，继续被动惯性、重力、环境作用及共用碰撞，世界与上涨水继续运行，完整播放后才接逃生失败遮罩或教学重载。`CharacterPhysics` 的被动运动只关闭角色主动驱动、跳跃和游泳等动作执行，复用箱子的共用物理底层，显式刷新恢复角色执行。菜单暂停仍停止物理而动画使用真实时间；进入失败渐变或加载后沿原暂停规则。表现层不结算费用或切换阶段，刷新、禁用、返回菜单和受理换关均作废旧等待。

`SceneChangeMgr.CompleteEscapePreparation(bool preserveScene = false)` 是准备最终确认后的统一入口，当前由原购买／低预算路径调用；消散完成后才保留／复位现场、安置实体、等待镜头抵达，再开放操作和涨水，不发送死亡请求或收转换费。新多项购买和负面确认面板后续复用此入口，当前尚未实现。隔离 Unity 实际流程验收入口为 `DeathAnimationFlowChecks.RunForBatch`，覆盖上述流程、重复死亡、暂停、退出和换关。

## 实体通关播放

实体通关图使用 2026-10-12 确认的人工调整版 `1791771631551.png`，原样导入 `sequence frame/catgirl-level-clear-0.png`，共八个 384×512 切片。原 PNG 的 RGB、Alpha 和文件内容保持一致，sRGB、无压缩、无 mipmap；通过 PPU=129.89691 和每帧自定义枢轴，将角色高度与脚底横纵位置对齐现有实体待机，修正原图两行不同的脚底位置，不改角色预设的缩放、材质或颜色。

通关道具的 `levelClearAnimation` 为动作编号，默认 0。后续编号 N 对应 `Base Layer.LevelClear_N` 与 `Base Layer.LevelClearLoop_N`，关联同名片段，前者不循环、后者循环，不新增 Transition 或动画事件。共享 `PresentationLayer` 仅在受理时校验指定编号，不要求精神体控制器提供通关片段。

`SceneChangeMgr.TryClearLevel` 校验当前实体、教学／逃生资格、下一关及动作配置，通过后立即撤销实体运动、输入和资源更新。普通交互与死亡反馈不再受理。场景编排读取真实 Animator 完成事实，前段完整结束后切入循环并开始原换关过场；保留同一实体及原进度、效果确认规则。加载安置保留循环，淡入完成后统一释放，恢复正常待机／行为。暂停时演出继续使用真实时间；返回菜单、其它换关和普通角色刷新作废旧等待。无效片段或播放被打断明确报错，不用固定延时触发加载。

未进入加载就退出等待时，`FinishLevelClear` 统一释放本轮受理与播放，并归还触发道具，保持道具当前位置。播放无效或循环启动失败时恢复受理前的角色许可与输入开关，菜单仍保留暂停；普通角色刷新沿其自身流程恢复许可。成功加载、返回菜单或其它换关已接管后，旧等待不能回滚后来状态，不推进关序或确认效果。

制作／对齐检查入口为 `CatgirlLevelClearAssets.ImportAndValidate`；真实道具、前段完成、加载循环、反馈锁定、跨关复用和取消联验为 `LevelClearFlowChecks.RunForBatch`，同次执行既有表现及道具交互回归，并覆盖前段打断、循环失效、菜单暂停、道具归还与重试。

## 运行时校验

初始化时检查普通动作必需 Animator 状态，缺失会输出明确错误并停用自身；死亡／退场受理前另行校验 `Death` 状态、片段及播放配置，避免状态名变更后静默播放错误动画。10/11 串联后原动作表现回归 512 项通过，证据见 `.utmp/DeathExitValidation/motion-checks.txt`。
