# 工程原则

当前分层与实现边界。任务优先级看[待办安排](待办安排.md)，整款玩法与数据所有权看[玩法大纲](玩法大纲.md)，代码入口看[项目 README](../README.md)，历史取舍看[历史回顾](历史回顾.md)。玩法接到本文的分层上；大纲没有要求时，不改这里的物理解算边界。

## 八条原则

1. **逻辑与宿主分开。** 宿主负责组装、调度、生命周期与场景引用；玩法规则尽量用普通类型表达。当前仍有 Unity 类型依赖，不宣称已完全引擎无关，也不提前建设万能适配层。
2. **单向管线。** 输入 → 实际类别 → 行为策略 → 执行 → 表现。下层不回写上层内部状态，跨层通过明确接口和只读数据。
3. **行为与执行分开。** 行为决定能否做、做什么；执行计算速度、位移和其它效果。FSM 不写 Rigidbody2D、不积分重力。
4. **感知与职能分开。** 几何只描述命中；环境能力解释效果。无脚本表面仍可阻挡，有几何接触不等于可墙滑。
5. **环境关系归实体。** EntityEnvironmentContext 核对来源并登记/撤销效果；源端 Registration 只保留身份与清理反向索引，不持有实体累计速度。
6. **按能力扩展。** 新效果优先接入窄接口，避免修改底层查询和全局时序；同层复杂组织不堆进一个总控类。
7. **角色四层组装。** 实际类别 Player 负责初始化和输入接入；PlayerStateMachine 负责行为；CharacterPhysics / BasicEntity 负责执行；PresentationLayer 只读输出。公共输入与调度不算第五层。
8. **配置外置。** 探测层、尺寸、开关等走配置资产；本阶段的算法常量须在后续定标时明确归属，不为改名同时迁移序列化数据。

## 当前边界

- 场景环境发现仍要求 Collider 同物体的唯一 BasicPhysicalObject；FindHost 对外返回 IEnvironmentSource。接口返回类型不等于可以发现任意纯 C# 来源。
- 脚下采样地面响应/平台位移，并按现规则登记持续效果；区域登记持续效果并采样独立水事实；侧面只解析墙滑。
- 接触查询排除 Trigger，区域事实只收 Trigger；不通过改全局查询开关影响其它模块。
- 无三类持续能力不建立 Binding；接口值为零仍是能力存在。表面采样不依赖 Binding。
- 当前使用 Dynamic 混合模式，箱体物理根节点冻结旋转；表现子节点的装饰旋转不改变实际碰撞。
- 旧 N=1、T+1、静墙后裁剪属于当前算法基线；后续统一建模可调整，但须明确时序与回归依据。

## 时序与数据

### 四向能力与环境扩展

P_5.3 已实现 `Player.ResolveFourWayAbility` 共用入口、不可变身份、外部能力许可、游泳行为和分别的运动/资源更新许可。游泳通过原水平/竖直速度钩子执行，着地时按世界双轴消费并保留一次平台携带。控制由外部选择，失去输入仍可更新环境与资源。水事实归 `EntityEnvironmentContext`，氧气归玩家 FSM，死亡请求携带明确死者并交规则层。

飞行仍是本游戏的穿墙模式，优先度最高；完整外部运动事实、能力、效果和 Unity 阻挡屏蔽**尚未实现**，由 `IPlayerFlightExecution` 留契约。未接形态执行与认知规则时不能提交飞行，也不能确认探索死亡完成。阶段、角色身份与输入所有权不被屏蔽取消，退出飞行重新采样环境。具体规则见[玩法大纲第 1 组](玩法大纲.md#1-阶段与能力开关)。

接口表示接入契约/类型支持，成员配置表示可编辑能力当前是否启用。平台位移等固有契约继续保留接口，数值与开关分开。水的 `SwimmingEnabled` 每次采样立即生效；固定水减速与二维流速复用持续效果协议。其余持续效果仍首次复制，运行时差异更新、水/冰/墙转换仍归 K_7，保持唯一宿主、稳定来源身份和既有相位。详见[环境能力与形态转换](环境能力与形态转换.md)。

### 当前时序与数据

物理槽按 0→5：平台运动/配置水位 → 几何 → 环境/能力 → 速度与预测 → 实体接触及环境约束 → 请求提交。每个参与运动的实体最终提交一次 MovePosition，不在接触迭代中反复写 Unity 世界。显式刷新可立即还原刚体与子探针位置、清运动缓存并重新采样，不作为第二条逐帧提交管线。

| 数据 | 归属与用途 |
|---|---|
| PlayerPhysicsData | 实体跨帧运动状态；verticalSpeed 含重力和跳跃，不能简单称为纯主动速度 |
| EntityEffectState | 实体效果数值的唯一持有者；保存移速修饰、限时/持续速度、动态力累计及退出尾效，不管理来源 Binding |
| GeometryPhysicsData | 本帧几何事实；isGrounded、onLeftWall/onRightWall 不代表表面能力 |
| PhysicalFunctionData | 角色相位 2 解析的左右墙滑能力；逻辑只读可用性，执行读取参数 |
| EntityEnvironmentFrame | 脚下参数快照；不保存累计速度 |
| EntityWaterFrame | 区域水事实；上缘中心淹没与同来源有效游泳候选分别汇总，不依赖持续效果 Binding |
| EntityWaterFrame 的水面扩展 | 半露出、同源水面游泳可用性与世界水面高度由相位 2 发布；不读按键、不拥有氧气或泳姿。角色能力汇总后交专用水面行为消费，原相位 3 稳定中心高度，表现读逻辑事实 |
| EntityMotionFrame | 本帧基础运动；plannedWorldDelta 供预测与提交复用。groundSlopeDeltaY 只记录地面切线产生的 Y，水平阻挡仅缩短这一分量，不从总 Y 猜坡面补偿；平台与世界竖直水流保持独立 |
| EntitySolutionResult | 本帧实体间偏置、环境修正、障碍允许的 X、请求位移和阻挡方向。相位 4 环境裁剪先写直接阻挡，残余回算后接触策略可向上游传播同向阻挡；该方向保留到下一帧相位 3 的效果汇总，随后在预测前归零。它不是推箱状态、平台 Delta 或跨帧速度 |
| PhysicalBoundingBox | 预测 AABB；size 表示半长宽 |

表现从只读事实推导状态，不以动画需求定义物理字段；位移偏置不等于“正在推箱”。请求位移与 Unity 最终落点须区分。

## 调试与回归

- 观测数据只能由运行逻辑复制，不能参与解算或回写速度、位置和登记关系。
- 仅编辑器观测的声明、赋值与专用计算放在 `#if UNITY_EDITOR` 内；混在运行时类型中的观测字段用 `debug` 前缀，公开入口用 `Debug`，注释标 `[EditorOnly]`。专用 Debug 快照内部字段无需重复前缀。
- 正式计算即使结果也用于显示，仍属运行逻辑，不能被移入编辑器宏。
- 用 fixedTick 区分物理帧。区分基础位移、接触偏置、静墙裁剪与 engineCorrection；不每帧大量打印日志。
- 回归区分编译、Edit Mode 集成和 Play Mode 场景验收，不互相替代。当前角色/箱体均启用插值作为用户确认的显示基线；不要用显示平滑反推物理解算正确。
