## 玩家经历的循环

人工设计的纵向关卡。世界先停住，玩家在有限范围里看、记、改少量环境属性，并决定留下哪些信息。留下的信息占用认知，剩下的认知变成逃生时的行动能力。然后水从下面涨上来，玩家用刚才的理解往上走，也可以靠近水面。失败清空局内状态，玩家本人的记忆留在人身上。

教学关没有漫游，没有格子，没有小地图。物理世界才有漫游、格子和模拟。

物理世界一次历程是四段，后三段受同一个阶段开关控制：

1. **漫游。** 玩家本体停在原地播待机。控制权交给旁边出现的精神体。
2. **探索。** 精神体结束、控制回到本体之后。不能操作场景机关，可以查看和修改场景属性。可以消耗认知，打开这一关的模拟。
3. **模拟。** 同一关的另一份场景。交互和修改都打开。箱子位置只在模拟里变。
4. **逃生。** 只能操作机关和推拉，不能再查看或修改场景属性。水上涨。

阶段只开关能力。规则层写环境数据，物理层读已经算好的参数。探索和阶段系统不写角色物理的内部控制流。

## 不能被后来的玩法盖掉的所有权

后面每加一个系统，先对这七条。对不上就停，不另开一套入口。

1. **环境属性只有一份来源。** 实际场景里改过的摩擦等属性，模拟场景里也是这份；模拟里改了，实际场景也变。箱子的世界坐标不写进这份来源。
2. **推拉是玩家身上的能力，不是箱子上的锁。** 能力打开后，多箱链可以推动，包括不与玩家贴着的箱子。
3. **收纳是箱子自己的状态。** 向内推入只断开和那只箱子的选中，不因此关掉玩家的推拉能力。
4. **带电方块仍是箱子。** 玩家不能对它打开交互；小车和隔着别的箱子的推动仍走接触。
5. **飞行开关只属于精神体。** 实体玩家的逻辑上不能打开飞行。实体若真的进入飞行，播放飞行动画并显式报错。
6. **格子只记录玩家走过哪里，以及少量特殊标记。** 小地图不画格子里的场景内容。格子不放进物理接触查询。
7. **现有物理解算相位不为新玩法重写。** 新行为接到已有接触、环境参数和阶段开关上。
8. **体力和氧气是玩家身上的同一类持续资源。** 各自记录当前值、消耗条件、归零时发生什么。水只提供「是否淹没」，疾跑只提供「开关是否开着」。归零后的摔倒若以后要做，接在疾跑这条「因归零而关闭」的结果上，不另做第二条体力。

## 系统

按代码会落在一起的玩法分组。一组里的后来功能必须接这一组已有的数据，不能平行再做一套。

### 1. 阶段与能力开关

漫游、探索、模拟、逃生、教学关，关的是同一组能力：能否推拉、能否操作机关、能否改场景属性、控制的是本体还是精神体、精神体能否飞行。

做法与现在的输入接入相同：能力由外部注入的开关决定，不在每个玩法里各写一个全局单例去改角色。教学关是这组开关的一个子集（没有漫游、格子、小地图），不是另一套游戏。

现有 `InputControlMgr`、改键面板和 `PlayerStateMachine` 可以扩展。游泳、交互、收纳长按、疾跑开关是新动作，加进现有输入动作和状态枚举，不更换输入资产或状态机类型。

| 控制 | 内容 |
|---|---|
| 快速迭代 | 阶段枚举、能力开关、把开关接到已有输入和状态机 |
| 人工把控框架 | 开关的归属就在这一节。新玩法要关能力时，加开关，不绕过阶段去改物理或改另一套输入 |
| 人工决策逻辑 | 无。各阶段哪些能力开着，上文已写明 |

### 2. 接触推动与拉动

能力打开后，玩家可以推，也可以拉。推沿用现有接触：箱子链、小车撞上箱子、玩家隔着箱子去推带电方块，都是接触推动。

拉是已有接触上的新方向：玩家正在远离箱子，且推拉能力开着，接触才把箱子往玩家一侧带。不为此新做约束求解，也不改写已有的水平阻挡传播。

| 控制 | 内容 |
|---|---|
| 快速迭代 | 多箱推、小车推、隔箱推带电方块 |
| 人工把控框架 | 拉动要改已有接触施力。开工前先确认：拉只在「能力开着且玩家远离」时进入现有接触策略。确认前不动 `CurrentAabbContactSolver` 的施力条件 |
| 人工决策逻辑 | 无。拉的条件上面已写明 |

### 3. 选中、向内推入、向外拉出

靠近箱子按下交互：打开玩家推拉能力，并选中这只箱子。选中不是锁。

长按同一个交互键：把选中的箱子向内推入。颜色变暗，碰撞器关闭，其它箱子在水平方向上不再被它挡住。这次与该箱子的选中断开。

箱子已经在内部时，玩家靠近后按同一个交互键，把它拉出。

同一个格子里已经有一只向内的箱子，外面的箱子不能再向这个格子推入。向外拉出时，目标格子上已经有箱子，也不能拉到同一位置。重合用格子占用判断，不用两只碰撞器叠在一起来挡。

| 控制 | 内容 |
|---|---|
| 快速迭代 | 选中、变暗、关碰撞器、拉出、按格子拒绝重合。依赖第 5 组的格子，但不依赖物理解算改动 |
| 人工把控框架 | 无。碰撞器关闭后，水平穿过是碰撞器不参与接触的结果，不另写「穿过」分支 |
| 人工决策逻辑 | 无。点按、长按、再按，都是同一交互键 |

### 4. 机关与带电方块

三类机关共用「有没有指定对象压在上面」：

- 自动小车：开动后沿路径移动，移动时用接触推动箱子。
- 普通压感：上面有玩家、箱子或小车即可。
- 带电压感：上面是带电方块才启动。

带电方块可以被推，规则同箱子。玩家能碰到它，不能对它按下交互，因此不能直接取得推拉。它由小车推，或由玩家隔着别的箱子推。

| 控制 | 内容 |
|---|---|
| 快速迭代 | 两种压感、带电方块的交互拒绝、小车作为会动的接触体 |
| 人工把控框架 | 无 |
| 人工决策逻辑 | 小车的路径是沿关卡里摆好的路线走，还是被物理力驱动。定之前不做小车 |

### 5. 地图格子与认知

物理世界把地图划成格子，用来知道玩家走过哪些格子，并由此改变认知资源。不用触发器。初步方案：用关卡给出的原点、格子尺寸和行列，在代码里做 AABB，判断玩家所在格。格子数据不进入物理接触的射线和扫掠。

小地图只画格子。特殊格子可以有一个标记。格子里面有什么场景，不画。

教学关不划分，也不显示小地图。

| 控制 | 内容 |
|---|---|
| 快速迭代 | AABB 格子、走过的集合、小地图只显示格子和特殊标记 |
| 人工把控框架 | 格子保持为独立的空间记录。不把格子做成物理触发器，也不把「当前格」写进接触解算 |
| 人工决策逻辑 | 认知容量怎么从「走过的格子」变成资源。日志否决了「走一格加一分」当作全部规则，倾向是留下来的信息占容量，剩余容量变成逃生能力。换算公式开工前由人定一条最小规则，例如先只验证「记住的信息换一种能力」 |

### 6. 精神体

漫游开始时本体待机，控制权交给精神体。精神体有两种形态：可穿墙飞行，以及和实体一致的行走。为实现简单，可以是同一个运动类，用开关决定能否飞行；形象和动画分开。

探索阶段不能操作机关，可以查看和修改场景属性（例如加大地面摩擦）。逃生阶段反过来。模拟阶段两种都打开。这些开关属于第 1 组。

| 控制 | 内容 |
|---|---|
| 快速迭代 | 控制权切换、飞行开关、穿墙、两套形象 |
| 人工把控框架 | 飞行开关不写入实体玩家。实体进入飞行视为错误，播飞行动画并显式报错 |
| 人工决策逻辑 | 无 |

### 7. 模拟场景

探索中消耗认知后，进入同一关的模拟场景。理解成场景换了一份，玩家位置不变。

环境属性读第 1 条所有权里的那一份来源，所以实际与模拟互相看得到改动。箱子的世界坐标只存在于当前这份场景：模拟里的推动不写回实际场景；模拟提供重置，重置回到这份场景的默认箱子位置；从模拟回到实际，同样按刷新理解，玩家位置保留，箱子回到实际场景的默认位置。

| 控制 | 内容 |
|---|---|
| 快速迭代 | 加载、重置按钮、退出。所有权按上面定死之后再写 |
| 人工把控框架 | 开工前确认加载只分两支：环境属性保留，箱子坐标回到默认。这是新的加载规则，不是去改物理解算。方案定下来之前不写加载 |
| 人工决策逻辑 | 无。保留什么、丢弃什么，上面已写明 |

### 8. 水、游泳、浮力方块

水从下向上涨。玩家被淹没后可以游泳，上下左右都要有输入。这是 `PlayerStateMachine` 的新状态，加上现有改键能登记的新动作。淹没期间消耗的是第 9 组的氧气，水本身不持有氧气条。

浮力方块是同一股水的一种用法：方块随着水位上升，玩家站在上面被带着上去。日志允许第一版先不做。若做，玩家仍用现有的着地与地面携带；方块自己去追水位。不另做流体。

| 控制 | 内容 |
|---|---|
| 快速迭代 | 上涨平面、淹没判断、游泳状态、新按键接入现有改键 |
| 人工把控框架 | 浮力若必须改写地面携带或接触解算，停住，先说明动的是哪一段已有物理，不在迭代里直接改 |
| 人工决策逻辑 | 这 21 天的第一版做不做浮力方块。最小可玩可以先没有它 |

### 9. 体力与氧气

体力和氧气都在玩家身上，结构相同：有当前值，在某种条件成立时持续下降，降到 0 时触发这条资源自己的结果。数值不写入环境属性，也不写入箱子坐标。进出模拟场景时，它们与其它局内玩家状态一起刷新，不单独保存。

**疾跑。** 玩家用按键开关。开启期间体力持续下降。体力到 0，疾跑自动关掉。玩家自己关掉时，不视为归零。结构上留出「因为归零而关闭」这一个结果；时间够再在这里接摔倒。现在不制作摔倒。疾跑只在行走时生效，飞行形态下开关不起作用，避免和穿墙飞行叠在同一个移动入口上。

**氧气。** 水淹没玩家期间，氧气持续下降。氧气到 0，这一局结束。结束方式就是全文已写的失败：局内状态清空，玩家本人的记忆留在人身上。不另做一套游戏结束流程。

| 控制 | 内容 |
|---|---|
| 快速迭代 | 两条资源、疾跑按键与自动关闭、淹没时扣氧气、氧气归零走已有失败 |
| 人工把控框架 | 无。水不拥有氧气条，疾跑不拥有另一套体力；摔倒只预留在「归零关闭」的结果上 |
| 人工决策逻辑 | 无。摔倒明确不在当前版本 |

## 和 21 天的关系

大纲是整款游戏的目标，不是这 17 天的任务表。日志第 8 节仍然有效：核心循环没验证之前，不做完整随机地图、大型肉鸽、通用公式编辑器、完整生态和多结局，也不借此重构物理框架。

最小可玩仍是一关：先看再跑、认知会占资源、至少能改摩擦、剩余认知至少换成一种能力、水上涨之后改过的地面真的影响行动。本文的机关、收纳、精神体飞行、模拟、浮力、疾跑和氧气，都是接在这个循环上的用法；循环本身不成立时，不靠加这些来补。
