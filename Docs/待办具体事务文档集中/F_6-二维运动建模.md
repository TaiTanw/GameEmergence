## F_6.2：运动契约语义修正（步骤 1–7 已落地，单元未完成）

**问题链路：** 原先 `GetPlanarVelocity` 是支撑处理前的速度，预测使用支撑和平台处理后的 `plannedWorldDelta`，接触却另读原始 X 速度；F_6.2_3 已将接触读数改为同帧自身运动，平台携带继续单列。实体间偏置仍只在预测 AABB 的较浅轴上求解。相位 5 再把基础位移与偏置相加，凭帧初贴墙标志把整段 X 清零，无法辨别可上坡表面、跳起后可越过的边缘和真正阻挡。阻挡结果没有及时约束接触施力或动态力累计。现码能解释这些风险，但尚未用场景观测证明每一处故障的唯一原因。

**本单元目标：** 固定相位 3 的运动数据含义；相位 4 按“实体间偏置 → 候选位置的环境约束 → 阻挡及接触反馈”求出本帧可请求的位移，并完成相应状态清理；相位 5 只提交一次 `MovePosition`。以推箱上坡卡住、跳上陡坡边缘卡住、冰面箱体顶墙仍积速三个可见问题是否消除，作为最终验收。箱体引擎旋转是此前提出的伴随需求，单列兼容检查，不把开放旋转直接等同于这些问题的修复。

| 阶段数据 | 本单元拟固定的含义 | 产生/消费边界 |
|---|---|---|
| 自由速度 | 效果、角色事件与重力等本帧更新后的世界速度，尚未按支撑面处理；沿用现有公式时等价于 `GetPlanarVelocity` | 相位 3 产生；不能冒充沿坡实际速度 |
| 自身运动速度 | 自由速度经过现有地面切线/竖直规则后的世界速度，不含平台携带 | 相位 3 与自身位移同时计算；相位 4 水平接触直接读取 X，不从位移除以步长反推 |
| 自身期望位移 | 自由速度经过现行着地/坡面规则后的本帧位移，不含平台、接触纠偏 | 相位 3 产生；不因字段拆分而偷改地面公式 |
| 平台携带位移 | 相位 2 的平台采样，按现行着地条件加入 | 与自身位移分开保存，避免后续误当成实体自身速度累计 |
| 预测世界位移 | 自身期望位移加平台携带位移，不含接触偏置和静墙裁剪 | 相位 3 生成预测 AABB；相位 4 接触判断须从同一帧快照选取明确的运动量 |
| 实体间位移偏置 | 相位 4 为解除实体间重叠求出的位移；X 是该接触对的水平分离量，Y 是该接触对的竖直分离量 | 不把整段偏置直接投影到坡面，也不把它当作速度或推动状态 |
| 环境约束修正 | 在基础预测终点施加实体间偏置后，针对有效阻挡/支撑求出的附加修正；可包含坡面需要的 Y | 查询用完整候选位置，修正量只描述偏置引发的环境需求；不重新积分速度或把基础位移折算成偏置 |
| 请求世界位移、阻挡结果 | 相位 4 协调基础位移、两类偏置及墙/坡/平台约束后得出；相位 5 消费 | `MovePosition` 请求不等于 Unity 下一物理帧的实际落点；记录被约束的方向供接触反馈 |

**坡面与阻挡的判定约定：** 若角度是坡面相对水平面的倾角，配置量应表达“最大可上坡角度”；低于该界限且确实形成有效支撑时，保留实体间水平纠偏 `x`，按候选位置的坡面几何补足 Y。已贴合直线坡面时可用 `y = x·tan(坡角)` 解释；实际计算仍须根据碰撞体形状、坡向、当前间隙和其它约束取需要的修正，不能固定套该式。超过可上坡界限则按障碍限制穿入；跳跃后若已越过边缘，应按本帧候选路径重新判断，不能只凭相位 1 的贴墙标志永久清零 X。单向平台须先判断该侧、该方向是否构成阻挡：从下向上穿过时，即使实体间接触给了向上 Y 偏置，也不由平台斜率再补 Y。

现有着地法线条件 `normal·up > 0.7` 约对应倾角小于 45.6°，侧墙条件 `normal·水平向 > 0.9` 约对应倾角大于 64.2°；它们来自不同探针与层掩码，不能合成一条完整的坡/墙判定。具体上坡角度和边界容差必须用场景标定，不能把现有阈值未经验证直接沿用。

### F_6.2_1 核对记录：现有类型与阶段语义（2026-09-25）

本步只分类现码与拟新增的结果，不改运行时数据类型或算法。速度单位为世界单位/秒，位移为世界单位，法线为方向；`Vector2` 只说明有两个坐标，不能由类型推断它是速度、位移还是法线。编辑器快照是观测副本，不是后续解算器的正式输入。

### F_6.2_2 落地记录：正式运动快照（2026-09-25）

`EntityMotionFrame` 新增只读 `freeVelocity`、`motionDelta`、`platformDelta`，与原 `plannedWorldDelta` 同帧构造。`freeVelocity` 是现有相位 3 全部速度更新后的世界速度，因此包含同帧已消费的跳跃/松跳结果，但不额外断言本帧是否已离开支撑；`motionDelta` 仍沿用着地切线及竖直标量公式，`platformDelta` 仅保存实际并入的值。预测与相位 5 继续读取原 `plannedWorldDelta = motionDelta + platformDelta`，编辑器观测改从该正式快照读取这四项。未改变 `phyVSpeed` 的着地规则、相位顺序、接触读速和 Unity 提交次数；下一步再决定相位 4 如何消费这些字段。

### F_6.2_3 落地记录：接触读同帧自身运动（2026-09-25）

相位 3 的预测 AABB 样本现携带生成预测中心的整份 `EntityMotionFrame`。坡面分支在原位移公式旁直接生成处理后 `motionVelocity`：空中等于 `freeVelocity`，着地等于竖直标量速度加地面切向速度。相位 4 的水平接触闭合与有向目标速度直接读取双方 `motionVelocity.x`，不再逐接触对用位移除以步长复原；位移计算式本身未改。平台 `platformDelta` 仍参与预测中心，但不作为实体自身接触力来源，延续原有“平台不写入 GetPlanarVelocity”的策略；平台携带实体挤压其它实体时是否需要力传播，待场景核对。实体间偏置、T+1 动态力容器、Y 轴只作几何挤出及相位 5 裁剪均未改。

### F_6.2_4 落地记录：候选环境原始几何（2026-09-25）

`PhysicsSolverMgr` 在本帧实体对纠偏全部累加后，逐实体调用 `ProbeCandidateEnvironment`。候选中心为相位 3 预测中心加 `displacementOffset`；用当前 BoxCollider 的世界 AABB 从当前位置扫向候选中心，并在候选中心查终点重叠。另从候选中心上方往下扫地面层，保留每个命中的法线、距离及单向平台组件身份。查询排除实体碰撞体与自身；它不写入 `nowGemetry`、环境来源或请求位移，旧相位 5 裁剪仍在。

向下命中的 `distance - downwardCastLift` 只是以候选底部为参照的**原始有符号间隙**。若扫掠起点零距离、先撞到顶面/天花板、法线不是有效支撑，或单向平台当前允许穿过，就不能把它直接当作地面约束。路径扫掠的零距离法线也不能直接用于坡角判定。`F_6.2_5` 要在所有命中中选择对本帧运动有效的面，再判定可上坡、障碍或可穿过；跳坡和单向场景的实际命中仍待 Play Mode 采样。

## 后续二维速度公式评估（F_6.2 之后）

在 F6.2 的阶段数据契约之上，再拆清**速度计算步骤**，并决定真正统一水平、竖直速度的公式。目标是让来源、事件、重力/支撑各有明确输入与输出，不再以“水平完成后再竖直完成”组织计算。以下仍是评估方向，尚未批准公式或后续单元编号。

| 候选步骤 | 本帧应明确的输入与输出 | 现码对应位置 |
|---|---|---|
| 1. 取本帧依据 | 几何支撑法线、重力方向、脚下参数和平台 Delta；确定输入基准方向 | 相位 1/2 的 `GeometryPhysicsData`、`EntityEnvironmentFrame` |
| 2. 更新效果数值 | 汇总移速修饰、持续/限时速度和动态力的跨帧积分；说明每类速度属于世界方向还是局部切向 | `EntityEffectState.UpdateMovementModifier / UpdatePassiveSpeed` |
| 3. 消费角色动作 | 根据输入方向生成主动速度；跳跃、松跳、墙跳只修改其应负责的运动状态，明确同帧事件优先顺序 | `BasePhysicsEntity.HActiveSpeedOperation → CharacterPhysics.PhyEventUpdate` |
| 4. 更新自由运动 | 在同一个二维速度状态中施加重力、墙滑等规则，得到尚未经过支撑约束的自由速度；明确事件与重力的先后 | `VUnderForce → VActiveSpeedOperation`、`GetPlanarVelocity` |
| 5. 处理支撑并形成位移 | 按支撑法线处理切向/法向速度；平台携带单列，得到本帧期望世界位移，供预测与提交共用 | `BuildMotionFrame → EntityMotionFrame` |

现码的逐步计算可写为：效果更新得到 `phyHSpeed/phyVSpeed`；输入得到 `horizontalSpeed = onMove · speed · (1 + nowPhyNum)`，随后事件可改写 `verticalSpeed`；空中再执行 `verticalSpeed += gravity · fixedDeltaTime`，着地则把负的 `verticalSpeed` 归零，最后墙滑可限制其下落值。此时 `GetPlanarVelocity = (horizontalSpeed + phyHSpeed, verticalSpeed + phyVSpeed)`。空中直接用该向量乘 `fixedDeltaTime`；着地却改用 `verticalSpeed · fixedDeltaTime` 加上“总 X 速度大小 × 地面单位切线”，因此 `phyVSpeed` 在着地位移中丢失。后续速度建模要拆开的正是这些**来源更新、事件消费、重力积分、支撑处理和位移积分**，不是只合并最终两个数。

步骤 2–4 的先后是待核对的运算顺序，不等于照搬现有调用顺序。跨帧累计状态与本帧合成速度需区分；本轮不预设将 `PlayerPhysicsData` 标量立即删除。相位 4 的接触力仍可能从下一帧生效；改变这一点需与 F2、V3/V4 一起评估。

### 已提出的方向约定

用户对输入速度方向的初步约定：**着地时沿脚下法线的垂线，空中时沿当前重力方向的垂线**，为将来的可变重力留出方向定义。按当前默认重力向下理解，左输入对应“支撑法线向左旋转 90°”；空中可先取重力反向作为参考法线，再向左旋转 90°。右输入取反方向。这里定义的是**主动输入速度的方向**，尚未决定外部状态速度、限时速度、动态力是否也随该基准旋转。

候选二维计算的暂定记法：输入轴 `s∈[-1,1]`、主动速率 `m`、单位参考法线 `n`，取右切线 `t=(n.y,-n.x)`，则主动输入速度 `v_input=s·m·t`；着地取 `n=normalize(groundNormal)`，空中取 `n=-normalize(gravityDirection)`。`m` 如何包含移速修饰、以及未来重力为零或方向突变时如何维持参考方向，均待确定。取得合成自由速度后，先按支撑规则生成自身运动速度 `v_motion`，再以 `v_motion·fixedDeltaTime + platformDelta` 形成期望位移；支撑规则尚未确定，因此这不是已批准的最终公式。

### 后续速度公式仍需收敛

- 着地时法向速度如何处理：向内的重力/外力、向外的环境速度和跳跃首帧分别何时保留、何时离地；不能直接沿用“丢弃 `phyVSpeed`”，也不能无条件加回。
- `EntityEffectState` 中持续速度已有世界 `Vector2`；限时速度、动态力当前只有 X 累计。要逐类确认方向与累计坐标，避免把世界速度误旋转为坡面切向速度。
- 事件、重力积分、墙滑限制与支撑处理的精确先后；尤其同一物理帧内跳跃和松跳的消费结果。
- `EntityMotionFrame` 要向后续接触判断暴露哪些**正式运行数据**，使接触读取与预测位移同义；不以编辑器观测副本代替解算输入。

后续速度公式的最小验收先看单体：平地/坡面左右输入、空中运动、向上/向下外部速度、起跳首帧和移动平台，核对预测位移与请求位移。平地多箱、坡面箱链及末箱抵墙是后续 F2、V3/V4 联合验收，不因 F6.2 通过而视为完成。
