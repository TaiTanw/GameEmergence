# K_10：输入动作、改键与唯一控制目标

2026-10-04 · **已回收。** `K_10.1`–`K_10.4` 代码已落地。编辑器验收随 `P_5` 一起看。游泳、疾跑、下平台、选中和收纳不在本项。

## 现码

| 位置 | 事实 |
|---|---|
| `DataAndInitMgr.LoadRebind` | 运行时把 `Resources/player` 的 JSON 替换 `<left>` `<right>` `<jump>` 后 `FromJson`。`player.inputactions` 不在这条链上。 |
| `InputControlMgr.BindInputAsset` | 把新资产赋给 `PlayerInput`，用匿名函数订 `Move`、`Jump` 和 `miniGame`。再次调用时无法卸掉旧订阅。方法末尾把当前动作图关掉。改键面板保存后会再调一次。 |
| `PlayerInputData` | 只有 `moveInput`、`jumpPressed`、`jumpRelease`。跳跃按下和松开都是边沿；`PlayerStateMachine.Update` 在状态更新后把这两个布尔清掉。 |
| `BindPlayer` | 参数非空时调用的是传入的那个 `Player.RemoveInput`，不是当前已经控制的玩家。然后把同一份 `PlayerInputData` 交给新玩家。 |
| `BasePlayerState` | `Init` 时保存输入引用。`PlayerStateMachine.Update` 虽收到新的输入参数，状态 `Update` 仍读初始化时的那份。 |

因此：改键会关掉正在使用的输入，旧回调留在被换掉的资产上。把控制权交给另一个角色时，旧角色的状态机仍握着原来的输入，一次性跳跃仍可能被旧目标清掉或重复响应。交互的点按和长按还不存在。

## 单元

按这个顺序做。后一个单元用前一个已经收束的入口，不并行改订阅和换人。

| 单元 | 闭环 | 验收 |
|---|---|---|
| `K_10.1` | `BindPlayer` 先解除**当前**控制目标。状态每帧使用玩家此刻持有的输入，不保留初始化时的旧引用。失去控制后不再写移动，也不再清一次性边沿。 | **代码已落地，未在编辑器验收。** 从角色 A 换到 B 后，只有 B 能移动和起跳；同一次跳跃只被 B 消费 |
| `K_10.2` | 去掉占位符替换整份 JSON。基础动作资产只加载一次，默认键位留在资产里；持久化只存绑定覆盖。再次绑定时先卸订阅，应用覆盖，再订上，并恢复绑定前的输入开关。`player.json` 与 `player.inputactions` 收成一个运行时来源。鼠标拖拽不进改键。开发期不迁移旧 `InputInfo.json`。 | **代码已落地，未在编辑器验收。** 运行时只加载 `Resources/player.json`。输入开着时改跳跃键，改完仍开着，且新键只触发一次 |
| `K_10.3` | 在基础资产和覆盖改键上增加交互。短按只产生点按，按住超过阈值只产生一次长按，两者互斥。边沿只交给当前控制目标清除。 | **代码已落地，未在编辑器验收。** 默认键为 `E`。短按写入 `interactTapped`，按住超过 0.4 秒只写入一次 `interactLongPressed` |
| `K_10.4` | 改键只接受键盘。点返回时扫描 `player` 动作图里已有键位；两条绑定的有效路径相同则在面板上提示，并留在改键面板。复合轴本身的 `1DAxis` 不算冲突。以后新增的键盘动作自动参与扫描，不另写一份按键名单。 | **代码已落地，未在编辑器验收。** 冲突文案写在面板底部的 `conflictT` |

`K_10.3` 只提供点按和长按事实，当前用控制台打印「交互点按」「交互长按」做测试，不进入状态机。贴合选中、再次点按解除、第二次长按收纳仍是 `P_3`。游泳、疾跑、冲刺以后各用自己的动作名，加进基础资产并订一次即可，不并进交互或跳跃。拖拽和 `miniGame` 已从运行时资产移除。改键面板可以改交互键。

`K_10.4` 不新开类型。改动停在 `InputControlMgr.StartRebind` 的键盘过滤，以及 `InputChangePanel` 返回按钮调用的一次冲突检查。预估小于 `K_10.2`，不改状态机和玩法大纲里的能力开关。

大纲里仍要先看现有结构才能定的，不是这一单元：拉动要先确认现有接触只在靠近时施力；浮力方块若要让人站在上面被水位带着上升，要先看地面携带。游泳的上下、疾跑和冲刺以后作为新动作加进同一张动作图即可，冲突检查会跟着扫到，不必先读状态机再定 `K_10.4`。
