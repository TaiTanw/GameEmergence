# 环境能力与形态转换

2026-10-08 · K7 差异更新与材料转换尚未实现，本文保留设计边界。P5.3 已有独立水事实、可变游泳开关与固定双轴效果，K11 已将真实动量交给刚体，现码交接见[P5](待办具体事务文档集中/P_5-玩家逻辑行为扩展.md)。玩法所有权见[大纲](玩法大纲.md)；不另起通用材料系统。

## 已确认的规则

- 环境查看修改只在探索／漫游的精神体飞行状态开放。模拟固定为同一精神体行走，漫游／模拟不再与形态任意组合；切换本身不刷新地图，模拟死亡回漫游并保留现场。完整费用、冷却、权限与刷新规则以[玩法大纲](玩法大纲.md)为准。
- 四向移动是一项角色能力，游泳和飞行接入同一个角色能力方法，保留各自来源和最终行为事实。阶段给许可，水域提供游泳可用性，精神体形态入口提供飞行启用事实。
- 飞行优先度最高，在本游戏中始终伴随穿墙。飞行期间外部水、着地、墙面、支撑平台和环境力场不改变有效能力或运动；不会因落入水域而变成游泳，也不耗氧。角色身份、输入所有权、阶段许可和主动形态切换仍生效。
- 水的主要职能是提供游泳能力与淹没依据；减速、水流等属于水域的物理效果，复用力场/环境效果通道。两者可同处一个环境来源，但不能用“有力场”代表“能游泳”。
- 可编辑环境不仅有摩擦等数值，也包含当前有效的能力。水结冰、墙变水方块是本轮要求评估的候选效果，尚未指定为 P_5.3 必须落地的玩法。

## K7 接入基线与现有缺口

| 代码入口 | 当前事实 | 缺口 |
|---|---|---|
| [EnvironmentCapabilities.FindHost / Find / IsActive](../Assets/Script/Framworker/Function/Physics/Data/EntityEnvironmentFrame.cs) | 唯一宿主经接口转换提供能力，IsActive 只检查组件存活/启用 | 接口支持与能力当前启用未分开；把倍率设为零也不会使接口消失 |
| [EntityEnvironmentContext.Attach / RegisterEffects / SynchronizeSources](../Assets/Script/Framworker/Function/Physics/Base/EntityEnvironmentContext.cs) | 来源仍命中且已有 Binding 时不重新登记；按接口存在保存三类持续效果凭据 | 同一个来源关掉一项能力，当前不会单独撤销这项；移速和持续速度改值也不会自动刷新 |
| [EntityEnvironmentContext.SampleGroundFrame](../Assets/Script/Framworker/Function/Physics/Base/EntityEnvironmentContext.cs) | 消退倍率、起跳加成和平台 Delta 每帧读取 | 这些数值本来就能运行时变化；不能把“所有环境参数都不可改”当结论 |
| [EntityEffectState](../Assets/Script/Framworker/Function/Physics/Data/EntityEffectState.cs) | 按来源保存移速、持续速度与动态力参数；真实动量归刚体，不保留来源速度库存或尾效 | 接收端有参数写口，但环境 Context 尚未按配置变化核对各项；不能绕过 Context 让编辑界面直接写实体容器 |
| [ForceField.CreateEnvironmentForce / ForceCalculation](../Assets/Script/Framworker/Function/Physics/Component/SceneObjects/ForceField.cs)、[BasePhysicsEntity.HActiveSpeedOperation](../Assets/Script/Framworker/Function/Physics/Component/PlayerOBJ/base/BasePhysicsEntity.cs) | 力场参数首次进入时复制，后续回调为空；当前动态力主要改变水平真实速度，移速修饰作用于主动命令 | 原类不能直接表示任意二维力。恒定二维水流沿 IStateVelocitySource 接入，游泳减速明确作用于哪些轴；完整二维力另属 K6 范围 |
| [Wall](../Assets/Script/Framworker/Function/Physics/Component/SceneObjects/Wall.cs)、[Taijie](../Assets/Script/Framworker/Function/Physics/Component/SceneObjects/Taijie.cs) | 墙滑由 IWallSlideSurface 和组件有效性决定；平台在相位 0 更新 Delta | Wall 的 canClimb 不是当前墙滑开关。平台 Delta 是运动契约，不应被材料能力菜单当作可删属性 |
| [BasicPhysicalObject](../Assets/Script/Framworker/Function/Physics/Component/SceneObjects/Base/BasicPhysicalObject.cs) | 同一物体只能有一个环境宿主，Registration 保持来源身份 | 不能把 Water、ForceField、IceGround 三个宿主叠在同一物体实现变形；应复用算法或在一个有限转换宿主内组合支持 |

C# 类型的接口支持集合不能靠改一个成员在运行时改变；但可以让预先支持的接口按成员配置返回“此项当前未启用”。运行时换组件/预设体不是唯一办法，也不建议把它作为普通环境编辑手段。

## 固有契约与可变成员

建议保持现有类型接口，增加有限的有效能力采样；让允许转换的宿主预先支持其转换集合，用成员配置选择当前启用项。无需让所有地面、箱子和机关实现所有接口。

| 类别 | 例子 | 规划边界 |
|---|---|---|
| 固有身份与生命周期接口 | IEnvironmentSource、IEnvironmentReceiver、Registration | 保留接口与稳定来源键，启停仍按生命周期清理；不作为玩家可随意增删的材料能力 |
| 固有采样/写入契约 | IPlatformMotion、IForceAction、物理查询/提交接口 | 平台 Delta 由真实平台运动产生，停住是零位移，不是失去接口。变水/变冰不自动赠送平台运动；本来是移动平台的转换物也不能漏掉应有的携带 |
| 可变行为能力成员 | 游泳启用、墙滑启用、减速启用、水流启用 | 是否生效是明确布尔或有限配置项，参数另存；允许水无水流、力场无游泳、墙阻挡但不可墙滑 |
| 可变参数成员 | 游泳范围/水面、墙滑倍率、地面响应、移速修饰、流速、动态力参数 | 由规则层维护一份运行时环境配置，采样或更新时读生效值；零值仍与关闭能力不同 |
| 可变几何状态 | Collider 的 enabled / isTrigger、允许的形状与层 | 控制物理发现与阻挡，不等于上面各项能力开关；只对允许转换的对象开放受控操作 |

接口表达“这个类型有实现此项的接入契约”，成员表达“这一项现在启用且参数是什么”。现有 Find/直接接口转换的消费点要统一读取有效能力结果：至少覆盖侧面墙滑、区域游泳、脚下参数和持续效果登记，不允许某一入口只看接口而忽略开关。采样可以表现为 TryGet/返回缺席或有限能力快照，具体方法名实施时收敛；当前不增加万能能力字典、反射插件或任意公式。

可转换宿主例如只支持水/冰，或只支持墙/水；其配置成员和算法覆盖这些形态即可。水的力场效果与游泳采样放在同一个唯一宿主的有效配置内，复用现有效果算法，不能再挂第二个 BasicPhysicalObject。内部采用普通参数/算法对象组合也可，来源关系仍由同一 Registration 表示。

“当前是水”“当前提供游泳”“几何上淹没”是不同信息：关闭游泳但仍是水时，可继续产生耗氧依据；转换成冰后不再是当前水来源。多水域逐来源判断，某一水源同时提供游泳并淹没才给出游泳候选，任一当前水源淹没则给出淹没事实；不得跨来源拼接条件。真正启用的水物理效果照常建立 Binding，只有游泳/淹没采样时不建虚假效果关系。

## 运行时更新需要补的最小边界

建议规则层统一修改环境配置，在既有相位 0 前或相位 0 提交本次改动，几何、能力与显示读取同一个已提交版本。相位 1–5 消费本帧一致结果，不在接触解算中途切 Collider 或替换来源。

首版按已确认的暂停编辑流程收束：漫游期间箱子、小车和机关暂停，只通过规则层编辑已开放对象；恢复模拟或开始逃生之前集中提交改动，核对有效能力差异、更新现有关系、重采样，再允许运动。不必先解决模拟运动过程中任意改材质的时序组合。统一环境来源与差异更新仍需保留：暂停的实体可能继续持有旧 Binding，不能只等它移出重入才更新；暂停箱子也仍可能占据准备恢复为实心的区域。玩家安全落点和固体占用检查不能因暂停而省略。提交未完成时不能报告恢复模拟／进入逃生成功。

EntityEnvironmentContext 在原相位 2 继续拥有关系，除核对来源进入/离开外，还核对同来源的**有效能力差异**：

| 变化 | 应做什么 |
|---|---|
| 原来关闭，现在打开 | 按该项首次登记，不重建其它未变化项 |
| 原来打开，现在关闭 | 按旧登记凭据撤销该项，保留同来源其它能力 |
| 能力不变，参数变了 | 通过现有写入口覆盖参数，保留刚体实际动量，不反复初始化运动状态 |
| 纯采样能力变化 | 水/墙滑/脚下参数重新采样，不为它伪造持续效果 Binding |
| 来源完全离开/禁用/销毁 | 沿原 Detach/ReleaseAll 撤销实际登记项 |

配置变化可用简单版本或必要的脏标识控制重采样，不先决定通用刷新框架。动态算法更换也必须刷新参数：已有 Binding 的来源不会仅因配置变化重新登记，不能假定重新 Attach 就读到新参数。

关闭持续速度意味着撤销该来源的速度项；关闭动态施力意味着停止驱动，但其已有惯性按退出规则保留/衰减。材料转换如需立即停止某来源惯性，必须在该项规则里明确，不默认清空所有环境速度。穿墙飞行另有有效运动屏蔽要求：外部作用关系与残余不能在飞行期间参与积分或提交；退出后重新采样，不恢复一份旧水/旧地面事实。

## 水结冰、墙变水方块是否合理

**在有限对象、固定几何和现有来源管线内合理；当前代码还不能只靠切 Trigger 完成。** 两种转换都由规则层改变同一环境来源的材料配置，不涉及生成流体、任意变形或新接触求解器。

| 转换 | 几何 | 能力与物理效果 |
|---|---|---|
| 水 → 冰 | 保留配置的边界，把水域改为实心、可被现有地面/墙查询发现 | 关闭游泳与水流，撤销原水效果；开启冰表面响应及配置允许的滑动效果。冰面参数走原脚下与效果通道，不只是改颜色 |
| 冰 → 水 | 取消实心阻挡，启用区域 Trigger，层配置允许现有区域查询命中 | 关闭冰表面能力，开启游泳；按有效水配置登记减速/水流 |
| 墙 → 水方块 | 固定墙块边界改成区域 Trigger，取消墙的实心阻挡 | 关闭墙滑，开启游泳与可选水效果；该水块是有限矩形水域，不自动并入下方上涨水、不生成流体。其水面/采样上界由自身配置提供 |
| 水方块 → 墙/冰 | 区域恢复实心前核对实体占用和几何层 | 撤销游泳/水效果，启用目标表面能力；被阻挡的角色如何安置必须先有规则 |

Trigger 是几何开关：isTrigger 为真意味着该 Collider 不当实心支撑/阻挡，但并不自动提供游泳；enabled 为假会让该 Collider 不再参与发现，也不是“只关闭减速”。固体同样能经脚下/侧面提供能力。第一版可用一个碰撞体受控切换实心/区域；若以后同物体多个 Collider，其接入身份和去重沿用唯一宿主，不放宽同物体多个环境脚本约束。

新增实心体时若角色/箱子仍在里面，直接切换会造成嵌入和原生纠偏，不能将这交给现有解算器自动保证安全。建议首版拒绝仍被实体占用的结冰/恢复实心请求；若玩法要求强制转换，再经规则层安全迁移、推离或延迟，需另行确定玩法。关闭阻挡的墙变水通常无需挤出，但要撤销原支撑/墙滑、重采样水事实并核对箱子落下。转换后的层矩阵、脚下/墙查询 mask、区域识别均要匹配。

漫游环境编辑既包括已开放的数值，也可在后续纳入这些能力／材料状态。它们归同一关卡环境记录：模式切换不刷新，试验重置与开始逃生的轻刷新保留，逃生失败的重刷新恢复默认；不把它们当箱子坐标或道具效果记录。水／冰／墙转换仍是后置候选，允许对象、形态及占用处置须在实际开工前确定，不因本轮规则确认而默认纳入首版。

## 当前交接

P5.4 与 K11 已实现，六相位统一原生模拟保留环境来源与参数归属，自动回归通过，人工手感与原场景待核；后续按[系统顺序](待办安排.md#后续系统实施顺序)接阶段、精神体、认知与最小环境编辑。冰面等手感只需可调，尚未最终定标。

地面响应已每帧采样，可直接复用；开放 Binding 内减速／水流编辑时再补能力开关和参数差异，保持来源身份与刚体实际运动。静态水与固定效果不等待完整 K7；材料转换、浮力及完整二维力场后置。真实飞行穿墙和外部作用屏蔽仍归 P7。

验收按实际开放范围覆盖：重叠内单项开关、同源多能力只退一项、参数更新保留状态、平台停住仍有身份、多人同源、飞行退出重采样，以及材料占用和轻重刷新。仅开关外观变化不能算效果更新。
